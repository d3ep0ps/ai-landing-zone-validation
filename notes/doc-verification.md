## T16 certificate (2026-10-25)
- Question: does an explicit-mode SECURE_WEB_GATEWAY (no TLS inspection) require `certificateUrls`?
- Verified (API reference, Gateway resource): `certificateUrls` is documented as "Optional. A fully-qualified Certificates URL reference." and "The proxy presents a Certificate (selected based on SNI) when establishing a TLS connection." and "This feature only applies to gateways of type 'SECURE_WEB_GATEWAY'." Only `routingMode` is stated as required for SWG ("This field is required for gateways of type SECURE_WEB_GATEWAY").
- Verified (quickstart "Deploy a Secure Web Proxy instance"): the Cloud Shell gateway.yaml (name, type, addresses, ports: [443], gatewaySecurityPolicy, network, subnetwork, routingMode: EXPLICIT_ROUTING_MODE) has NO certificateUrls. The console step says "For Certificate, select the certificate that you want to use to create the web proxy." (not labelled optional or required). The page says "We haven't configured TLS inspection in the example" and lists roles/certificatemanager.editor under required roles.
- Verified (frontend mTLS page): "The client initiates an HTTPS CONNECT request to the Secure Web Proxy frontend." and "the client validates the proxy's server certificate" (in the mTLS flow). The page does not say how the server certificate is provisioned or whether it is mandatory without mTLS.
- Release notes (docs.cloud.google.com/secure-web-proxy/docs/release-notes): no entry making certificates optional or required was found.
- Fabric vendor/fabric/modules/net-swp: variables.tf `certificates` is `list(string)`, `nullable = false`, `default = []`, no validation; main.tf passes `certificate_urls = var.certificates`. So the module does not require it.
- infra/v11-swp.tf (read only): `swp_certificate_url` described as required when swp_enabled, enforced by a precondition (`var.swp_certificate_url != null`), and passed as `certificates = [url]` or `[]`. This precondition is stricter than docs and Fabric.
- Verified command: none run (read-only check). Option A (docs-supported): create the gateway with no certificateUrls, as in the quickstart YAML. Option B (fallback if the API rejects it): regional self-managed Certificate Manager cert, `gcloud certificate-manager certificates create NAME --certificate-file=FILE --private-key-file=FILE --location=REGION` (flags not re-verified in this check). A Google-managed regional cert needs a domain/DNS authorization or a CAS issuance config; not verified for an internal IP without a public domain, so self-managed self-signed is the practical fallback.
- Expected error signature: if a certificate is in fact required, gateway creation fails at the Network Services API (not verified; no doc text found for the message).
