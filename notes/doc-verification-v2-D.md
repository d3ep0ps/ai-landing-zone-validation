## E2.7 Organization policy dry run
- Supported constraints (https://docs.cloud.google.com/resource-manager/docs/organization-policy/dry-run-policy): "Custom constraints," "Managed constraints," and certain legacy managed constraints: Restrict service usage, Restrict endpoint usage, Restrict TLS versions, Restrict TLS cipher suites. "Other constraints return an error if used in dry-run mode." Plain legacy booleans (for example `iam.disableServiceAccountKeyCreation`) are NOT supported in dry run; the managed equivalent `iam.managed.disableServiceAccountKeyCreation` is.
- Command: define `dryRunSpec:` with `rules:` and `enforce: true` in the YAML; "Set both `spec` (live) and `dryRunSpec` in one file to configure both modes." Apply `gcloud org-policies set-policy POLICY_PATH --update-mask=UPDATE_MASK`; docs say use `dryRunSpec` to update only dry run, `spec` for live only, or `*` for both; "Omitting `--update-mask` on an existing policy causes an error". DISCREPANCY: local `gcloud org-policies set-policy --help` says the mask values are `policy.spec`, `policy.dry_run_spec` or `*`, and "If the policy does not contain the dry_run_spec and update-mask flag is not provided, then it defaults to policy.spec". Use `--update-mask='*'` or test the exact value on first use (UNVERIFIED which of `dryRunSpec` / `policy.dry_run_spec` is accepted by the installed gcloud; `*` is accepted by both texts).
- Roles: `roles/orgpolicy.policyAdmin` on the organization (same page). Logging config writer only for aggregated sinks.
- What is logged: log `projects/PROJECT_ID/logs/cloudaudit.googleapis.com%2Fpolicy`; `protoPayload` fields `serviceName`, `methodName`, `resourceName`, `status`, `metadata`; metadata has `constraint`, `checkedValue`, `liveResult`, `dryRunResult`, `@type` = `type.googleapis.com/google.cloud.audit.OrgPolicyDryRunAuditMetadata`. Sample entry: status code 7, `liveResult: ALLOWED`, `dryRunResult: DENIED`, severity WARNING. "To find these entries, filter for `dryRunResult = "DENIED"` and `liveResult = "ALLOWED"`." Dry-run violations "don't block operations."
- Delay: dry-run page gives none. General page (https://docs.cloud.google.com/resource-manager/docs/organization-policy/creating-managing-policies): "Changes to organization policies can take up to 15 minutes to be fully enforced." Log arrival delay UNVERIFIED; poll.
- Hierarchy (https://docs.cloud.google.com/resource-manager/docs/organization-policy/understanding-hierarchy): boolean rules don't merge: "If a policy is specified on a resource, that TRUE or FALSE value is used"; example "The enforced: true value set on the folder is ignored because enforced: false is defined on the project itself." For managed constraints: "A resource that inherits a managed constraint enforces the constraint as it was set on the parent resource" and a child can override with its own policy; inherited managed constraints aren't merged. Tag-conditioned rule syntax (https://docs.cloud.google.com/resource-manager/docs/organization-policy/using-constraints): `resource.matchTag('TAG_KEY', 'TAG_VALUE')`; "a policy with a conditional rule must include at least one unconditional rule".
- Exception mechanism recommended: project-level policy with `spec: rules: - enforce: false` (simplest; no tag setup). `inheritFromParent` applies to list/merge semantics, not needed for a boolean/managed override. Does a project dryRunSpec exception also silence the dry-run log? UNVERIFIED (test it: the exception project should log nothing).
- Syntax (using-constraints page): `name: organizations/ORGANIZATION_ID/policies/CONSTRAINT_NAME` then `spec: rules: - enforce: true`. Delete: `gcloud org-policies delete CONSTRAINT (--folder|--organization|--project)` (confirmed in --help). Effective: `gcloud org-policies describe CONSTRAINT --effective --project=PROJECT_ID`.

Why: already proven at folder scope in T02 (attempt `gcloud run deploy ... --no-invoker-iam-check`, error text `Operation denied by` ... `run.managed.requireInvokerIam`, secondary source), no effect on Terraform state, quota project or the operator's IAM, and it only blocks one opt-out flag.
