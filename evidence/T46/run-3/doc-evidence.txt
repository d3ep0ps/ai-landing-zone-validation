## T46 (B7): DPoP for agent tokens through Agent Gateway
- Design (VERIFIED, access-context-manager/docs/caa-agent-security, re-fetched): CAA with DPoP is the documented mechanism behind the gateway. "When Agent Gateway is enabled, however, the gateway terminates mTLS, so DPoP must be used." DPoP is "based on RFC 9449". Parts: authorization DPoP proof "generated by Agent Identity when an agent is initially assigned an identity"; resource DPoP proof "generated by Agent Gateway and provided to Google Cloud APIs" (the gateway uses IAP to produce it); CAA "cryptographically verifies" both proofs came from "the same private key in the agent identity pool"; "Agent identity pools are provisioned with the key pairs needed for DPoP operations." Default CAA on, opt-out env var `GOOGLE_API_PREVENT_AGENT_TOKEN_SHARING_FOR_GCP_SERVICES=False`.
- Client-side support (VERIFIED by source): `google-auth` 2.62.1 (latest on PyPI today), `google-cloud-aiplatform` 2.6.0 and `google-adk` 2.13.0 contain NO `dpop` code (grep: only an unrelated minified JS chunk in the ADK dev UI). The only binding code in google-auth is certificate binding: `identity_pool.py` adds `bindCertFingerprint` to the STS token request, `compute_engine/_metadata.py` requests a bound token from the metadata server, both gated by `should_request_bound_token`. So the agent code does not generate DPoP; per the doc it is the platform (identity pool keys + gateway). No user-configurable DPoP switch is documented.
- NOT FOUND: any doc or release note that says DPoP works end to end for a Vertex AI (aiplatform) call through Agent Gateway; any google-auth changelog entry for DPoP. Release notes (gemini-enterprise-agent-platform/release-notes, read in full except the tail): only 2026-08-31 mentions "Context-Aware Access (CAA) with Demonstrating Proof of Possession (DPoP)" (in the IAM Unified Access Policies GA entry); 2026-04-22: Agent Identity GA, Agent Gateway "Private Preview". Docs search today also says Agent Gateway is in Preview.
- Open GitHub issue googleapis/python-aiplatform#7209 (v2-B-401 notes) is the only evidence of the 401 with DPoP as the documented path; no Google reply recorded as of 2026-10-28; not re-checked here.
- Verdict: T46 outcome = "documented design, no documented way to enable/verify it from the agent, no client support" -> NOT_TESTED with the above is justified; if attempted, the only lever is the gateway/IAP side (v2-B-iapv2 notes), not agent code.
- URLs: https://docs.cloud.google.com/access-context-manager/docs/caa-agent-security ; https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes ; https://pypi.org/project/google-auth/ (2.62.1, source read from wheel)
- Confidence: high (design, no client DPoP code); low on end-to-end status.
